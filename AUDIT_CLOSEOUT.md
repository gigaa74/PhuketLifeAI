# Закрытие технического аудита

Дата фиксации: 25 августа 2026 года.

## Закрыто кодом

- Персональные данные обезличиваются до передачи внешней AI-модели.
- Для ручных лидов действует срок хранения 30 дней и ручное удаление.
- Отправка клиенту и партнёру требует решения владельца; автоматическая
  рассылка отключена.
- Внешние вызовы имеют ограниченные повторы временных ошибок, клиентские
  сообщения ограничены по частоте, журналы не содержат исходный текст и контакты.
- Telegram application errors обрабатываются централизованно; `RetryAfter`
  фиксируется только как безопасная длительность ожидания, без текста запроса.
- Одобрение партнёрской заявки, создание или связка партнёра и выдача active
  статуса выполняются одной транзакцией с rollback при конфликте.
- Клиентская логика вынесена из большого entrypoint в отдельные модули.
- `.gitignore` закрывает базы, сессии, backups, временные файлы, выгрузки,
  вложения и распространённые форматы закрытых ключей/сертификатов.
- Неиспользуемые Scout runtime и конфигурация удалены. Историческая схема базы
  сохранена без разрушительных migrations.
- Новые партнёрские приглашения имеют срок действия 24 часа и остаются
  одноразовыми.
- GitHub Actions проверяет compilation, полный suite и известные уязвимости
  Python-зависимостей при push и pull request.
- Добавлена единая команда SQLite backup через штатный backup API с проверкой
  целостности источника и копии.

## Принятое владельцем ограничение

В приватной Git-истории могут оставаться ранее добавленные реальные
партнёрские данные. Владелец разрешил проверку приватного репозитория доверенным
человеком. Этот репозиторий нельзя делать публичным или передавать третьим лицам
без отдельной очистки истории и повторного secret/PII review.

## Системные меры вне кода

Эти пункты нельзя честно закрыть изменением Python-кода:

1. Включить шифрование диска Windows (BitLocker или эквивалент) и ограничить
   доступ к папке проекта учётной записью владельца.
2. Хранить резервные копии на зашифрованном носителе и периодически проверять
   восстановление.
3. Отозвать в BotFather токены двух выведенных из эксплуатации Scout-ботов,
   сохранив их usernames за Phuket Life.
4. Перед публичной публикацией создать отдельный обезличенный репозиторий;
   переписывание истории рабочего репозитория без отдельного окна обслуживания
   запрещено.
5. До постоянного круглосуточного запуска выбрать контролируемый процесс:
   ручной запуск владельцем либо Windows-служба с мониторингом. Сейчас принят
   ручной запуск одного основного бота.

## Решение по Scout

Partner Scout и Client Scout больше не являются production-компонентами.
Новые кандидаты находятся владельцем вручную и пересылаются основному боту.
Старые записи `scout_candidates` не удаляются и не используются для outreach.
